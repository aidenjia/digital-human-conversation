# 自动解释动作

用户已同意先完善现有解释动作并接入自动触发。本轮沿用现有异步意图分类与本地素材调度，不训练模型、不扩充其他动作。

## 行为

- 在 none/greet/agree 之外新增语义意图 explain；实际素材 ID 仍由前端目录选择。
- 助手开头正在讲解原因、机制、区别或步骤时可返回 explain。单纯问候、简短确认、安慰、翻译、引用、显式身体动作指令不触发解释动作。不能只看用户问句或“解释”关键词。
- 沿用每轮一次异步判断、不阻塞音频、1500 ms 有效期、8 秒全局冷却、30 秒同意图冷却；只有实际播放回执消耗后端冷却。
- 现有 explain 素材通过当前模型的必要骨骼检查后预加载并允许自动选择；不就绪或失败则跳过，不现场等待下载。
- 保留默认礼服的新待机落点、解释动作适配与打断淡出；摇头继续试播。
- 继续只支持 opening cue，本轮不增加多语音片段规划。

## 选择

采用现有分类模型新增语义意图。关键词规则难以区分讲解与提及讲解，增加独立分类调用又没有必要；现有单次判断即可完成。

## 验证

先增加协议、预加载、自动调度及冷却回执测试并观察旧实现失败，再更新 Schema、提示词和动作目录。运行真实模型的合成语义样例，记录样本结果而不推断生产准确率。执行完整 Maven verify、前端 Node 测试、lint/build，并在 ego 浏览器检查解释播放及打断后的恢复。浏览器事件注入只能证明渲染/调度，不能替代真实音频链路。
