# 可扩展动作意图与调度设计

已确认范围：保留每轮一次异步判断，自动行为仅问候/告别和赞同；先建立同轮多 cue 的协议和队列，后续再启用分段判断与真实播放同步。WebRTC 为主验收路径，PCM 保持协议一致。

## 边界

- 后端仅输出语义意图 none/greet/agree 和表情，不选择素材。greet 包含问候与告别。
- 动作目录负责具体 ID、来源、准入、加载策略、必要骨骼、优先级和适配策略。
- 前端调度器负责回复和 cue 去重、片段绑定、有效期、可用素材选择、冷却与显式命令抑制。
- 播放器只接受已经准备好的轨道，支持增量注册和连续恢复；解释动作的已有适配保持不变。

## 协议

模型返回仅含 intent/emotion。服务端追加自己的 responseId、cueId、segmentId 和 expiresInMs：

```json
{"type":"avatar.decision","responseId":"r1","cueId":"opening","segmentId":"opening","intent":"greet","emotion":"happy","expiresInMs":1500}
```

实际开始后回执：

```json
{"type":"avatar.gesture.started","responseId":"r1","cueId":"opening","intent":"greet","motionId":"wave"}
```

cueId 在 responseId 内唯一；只接受匹配、未过期、未确认的建议回执。前后端同步升级，旧 gesture 协议不兼容，必须刷新页面。

## 调度与加载

- 保留全局 8 秒及同意图 30 秒冷却。不同素材共享同一意图冷却；本次尚未开放密集动作序列。
- 同轮允许多个不同 cue，主体不重叠；繁忙时等待到有效期，过期直接丢弃。表情在对应片段说话时独立应用。
- 每轮队列最多 32 项，最多记忆 256 个 cueId；跳过原因保留最近 64 项。按优先级、避免重复上个同类变体、ID 排序进行确定性选择。
- opening 为当前生产默认片段。未来真实播放适配器调用 markSpeechSegment(responseId, segmentId)；未来片段未进入则等待，已播放片段的迟到 cue 丢弃。文本到达不被当作真实播放边界。
- 新回复、取消、用户打断清除旧队列；显式动作阻止当前轮后续自动动作；停止按钮也取消尚未完成的试播请求。
- 仅挥手 JSON 预加载；解释、摇头点击后按需加载。自动动作不等待下载，不补播已错过的建议。
- 挥手素材为 approved；点头为 legacy 程序动作；解释/摇头为 preview，不能自动触发。摆动与爱心继续保留为手动 legacy 效果。
- 每角色有独立加载器，合并同资源请求、失败可重试、销毁后忽略旧结果。换角色重新适配，不复用上一个角色的动画轨道。
- 默认裙装的前倾待机参数仅作用于默认角色；导入角色仍需完整视觉验收。只有已有验收挥手允许复用旧本地素材。

## 验收边界

自动测试覆盖协议、冷却、同轮队列、增量加载、换角色竞态及现有真实骨骼/裙面回归。浏览器试播和真实语音首播/动作时序属于另一级证据，不能由这些测试代替。

分段模型调用、缩短全局冷却、新动作自动准入、精确语音同步和新素材生成不属于本次交付。
