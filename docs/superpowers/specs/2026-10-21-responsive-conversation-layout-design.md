# 实时数字人页面自适应布局

日期：2026-10-21

## 目标与范围

按用户确认的方案，放大当前 PCM / WebRTC 实时对话页：宽屏人物与对话左右排列，窄屏上下排列。仅改变页面结构、样式及字幕滚动定位，不改变音频、模型、人设、动作判断、冷却或会话协议。旧版 Conversation、登录和模式选择页面保持原样。

## 当前限制

共享 `.app-container` 的 max-width 为 800px、height 为 80vh；`.avatar-stage` 的 max-width 为 640px，画布最高 480px。人物和字幕位于同一个纵向区域中，窗口较小时容易相互挤压。

## 已确认布局

- 实时页使用独立的作用域类，移除该页的 800px / 640px 宽度限制，随可用浏览器窗口伸缩，不要求浏览器全屏。
- 宽屏（可用视口宽度至少 1024px）：页头横跨顶部，内容使用约 3:2 双列；左侧人物面板占约 60%，右侧会话面板占约 40%。两列均允许收缩，避免长文字撑出屏幕。
- 人物面板保留画质、视角、模型导入、待机、动作预览等现有操作；画布填充剩余高度。状态说明和按钮不覆盖人物，也不靠缩放整个网页实现放大。人物镜头继续使用现有半身/全身适配逻辑。
- 会话面板连接前显示现有人设、音色、模型、输入方式及动作素材工具，连接后显示字幕；配置与字幕占据可滚动区域。
- 输入框、发送、开始/结束会话和错误提示位于会话面板底部，不随历史字幕滚出可视区域。字幕更新只滚动字幕容器，不将整个页面或输入框滚走。
- 窄屏（小于 1024px）：人物在上、会话在下；画布高度随视口调整，允许页面纵向滚动。会话具有有界高度、内部字幕滚动及可见输入区；不设置过大的固定最小宽度。
- 使用动态视口高度 `dvh` 并提供 `vh` 回退；小屏软键盘缩小可用空间时不以固定 80vh 隐藏输入控件。极矮窗口允许面板/页面纵向滚动，优先保证操作可达，不承诺所有工具按钮始终同屏。
- 页头、工具栏、操作按钮允许换行，手机端缩减外边距；不出现横向溢出。

## 结构与样式边界

`ConversationRealtime.tsx` 将人物和会话拆成稳定的两个面板，不因连接状态变化卸载人物或重建 hook。会话操作区随右侧面板布局，保留现有事件绑定和输入键盘行为。

布局样式通过实时页作用域限定，避免改变旧页共享样式。人物组件样式在实时页中覆盖宽高约束，不改动画、渲染质量、模型比例及动作素材。若需要新增样式文件，显式在实时页导入，保证开发热加载和生产构建下覆盖顺序一致。

## 验收

- 桌面至少覆盖 1920×1080、1366×768；人物与会话左右排列，占用接近整个视口，输入区可见。
- 平板/手机至少覆盖 768×1024、390×844；人物与会话上下排列，长字幕和工具栏不造成横向溢出。
- 低高度窗口检查控件可达、配置可滚动，不被外层 overflow 隐藏。
- 在 Chrome 中验证连接前配置、连接后文字问答、多轮字幕滚动和人物操作；调整视口后恢复浏览器原设置。测试会话结束后关闭。
- 前端行为测试、lint、生产 build 通过；保留当前已有构建告警的说明。布局几何与视觉效果必须在真实浏览器检查，不用样式字符串测试冒充自适应验收。

## 不包含

新增聊天功能、模型/动作调整、可拖动分栏、全屏 API、全新配色、旧页重构及后端修改。

## 审阅状态

用户已确认书面设计。前端布局已实现，Chrome 实际几何检查覆盖宽屏、笔记本、平板、手机和低高度窗口；连接后的字幕独立滚动和输入可见性已实测。记录见 `docs/responsive-conversation-layout.md`。
