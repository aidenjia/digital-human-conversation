# VRM 数字人验证

百炼 WebRTC 实时对话页面接入 Three.js + React Three Fiber + three-vrm。
现有服务端协议不变；传统 Agora ConvoAI 页面未接入角色舞台。

## 启动

在 `conversation-ui` 目录执行：

```powershell
npm install
npm run dev
```

依赖现已安装，锁文件已更新，TypeScript 与生产构建通过。后续全新安装可以使用 `npm ci`。

登录后选择百炼 WebRTC 模式，页面尝试加载本地默认角色 VRoid 官方 AvatarSample_2（ビビ）。
默认模型路径为 `public/models/avatar-sample-2.vrm`，大小约 17.1 MiB；按要求不提交此二进制文件，已加入 Git 忽略规则。全新检出后需自行准备有权使用的素材放到该路径，来源及许可说明见同目录 README。也可在页面点击“导入 VRM”选择自己的本地角色。
点击“导入 VRM”可替换为本地角色，点击“默认角色”可恢复。导入文件通过浏览器 Blob URL 加载，不会由页面上传到服务端；刷新后恢复默认角色。

## 模型建议

- 支持 VRM 0.x / 1.0；建议使用小于 50 MB 的单个、自包含文件。
- 需要 `aa` 嘴型、`blink`、相应情绪表情绑定；缺失表情时该表情无法展示。
- 建议先控制在约 5 万三角面、1K / 2K 贴图，减少材质数量、透明头发和弹簧骨骼。
- 上述为 780M / 16 GB 设备的起始预算，实际帧率仍须实测；文件大小不等于运行时内存占用。
- 请使用拥有相应使用许可的角色。

## 已实现

- 自动意图支持问候、赞同及解释：解释素材在骨骼兼容时预加载，收到 `explain` 后等待语音播放信号触发；摇头仍仅供试播。每轮仍只判断开头一次，保留冷却、过期和打断规则。
- WebRTC：分析远端媒体流，保留原有 Audio 元素播放，不增加第二路可听输出。
- 音量 RMS 经静音阈值与时间平滑映射到 `aa`；这不是音素级准确对嘴。
- `speech.started` 收嘴、进入聆听、取消手势；声音取消由既有服务端 / DataChannel 链路处理。
- `speech.stopped` 退出聆听；断开会话后音频读取器与角色状态复位。
- 本地眨眼、呼吸、头部微动、相机注视；情绪按钮提供表情预览，`heartbeat` 联动开心表情。
- 每帧更新直接作用于角色对象；默认清晰模式 DPR 为 1.5～2，启用抗锯齿；流畅模式 DPR 为 1。不启用实时阴影，清晰模式渲染上限 60 FPS，流畅模式上限 30 FPS。
- 本地模型替换、隐藏角色、卸载场景时释放模型和 Blob URL；隐藏仅停止 3D 更新，音频分析随会话结束释放。

| 命令 | 当前行为 |
| --- | --- |
| `dance` | 6 秒程序化上身摆动；尚无完整舞蹈动画素材 |
| `heartbeat` | 爱心特效与开心表情 |
| `zoom_in` / `zoom_out` | 平滑调整角色展示比例 |
| `change_scene` | 切换背景颜色 |
| `reset_default` | 恢复默认姿态、表情、比例、背景 |
| `wave` / `nod` | 本地预览及语音指令触发（需重启更新后的后端） |
| `sing` 等其他命令 | 不模拟对应能力 |

## 限制

表情目前使用客户端少量明确短语规则，不是通用情感理解模型；服务端新增回答生命周期和字幕的回答 ID，客户端也支持带回答 ID 的表情事件。
动作采用标准化骨骼上的程序化姿态，不是动作捕捉或预制 AnimationClip。
不同角色的肩部、表情覆盖规则、眼神和弹簧骨骼需要实际调校。
WebRTC 分析远端流与 Audio 元素输出之间可能存在设备播放延迟，需要实机观察音画同步。
首次加载模型仍可能短暂阻塞主线程；30 FPS 是渲染上限，不是性能保证。

## 验证

真实模型骨骼/挥手测试要求先准备上述本地默认角色；模型缺失时不应将相关测试失败误报为已通过。普通前端编译构建不依赖该二进制文件。

```powershell
node --test tests/avatar-runtime.test.ts tests/avatar-behavior.test.ts tests/arm-pose.test.ts
npm run lint
npm run build
```

独立行为测试需要 Node 24（原生 TypeScript 支持）。
联网安装后在百炼 WebRTC 模式验证：

1. 导入具有嘴型和表情绑定的角色，预览动作，检查肩膀和手臂是否自然。
2. AI 连续回答，确认口型随播放变化；静音和回答结束后收嘴。
3. 在回答中开口打断，确认声音、嘴型及聆听状态联动；下轮回答可以恢复。
4. 在 AI 说话时触发动作，确认语音播放不被动作事件清空。
5. 结束对话、返回模式页、重新连接，确认麦克风与旧会话不残留。
6. 替换模型、隐藏再显示、导入无效文件，确认语音功能仍可使用。
7. 在目标 780M 机器运行至少 10 分钟，观察帧率、内存和浏览器控制台；必要时先隐藏角色比较音频延迟。

TypeScript 与生产构建已通过。真实会话音频同步及目标机器性能仍需验证；角色浏览器验证结果见 OpenSpec verify.md。

## 清晰度

初版为了集成显卡性能，将 DPR 固定为 1 并关闭抗锯齿。这会减少高 DPI 显示器上的实际像素，轮廓也容易出现锯齿。现在默认使用清晰模式（DPR 1.5～2）与抗锯齿，可在角色工具栏切换流畅模式（DPR 1）。清晰模式像素开销最高约为原来的四倍，目标机器性能仍需实测。默认镜头现为半身近景，画布高度增加；面部占据更多屏幕像素，也可以点击拉近观察。模型原始脸部纹理为 1024×1024，躯干及服装为 2048×2048，没有额外进行纹理压缩或模糊后处理。

手臂放松姿态根据标准化骨骼的实际方向推导，兼容 VRM 0.x 与 1.x 朝向差异。回归测试使用内置角色骨骼验证左右肘均低于肩膀，避免初版旋转符号相反导致持续举手。

2026-11-04：默认礼服角色的待机上臂前倾由 0.22 弧度调为 0.04 弧度，配合小幅侧向间距，让挥手结束后的双手落在裙子两侧。默认角色挥手只播放右肩、右臂和右腕轨道，躯干与左臂保持待机，避免从素材的前伸姿势恢复时擦过裙摆。导入模型保留原有姿态与挥手适配。回归检查覆盖结束及打断后的落点、静态手腕/手指采样点到真实裙面的 8 mm 间距，以及挥手和解释动作的手指骨骼线段与裙面相交检查；这些检查不等于完整手部网格碰撞验证。

## 静态展示校准

自然待机现默认开启，按聆听、思考、说话和待机状态控制视线及轻微姿态。可以点击“自然待机：开”关闭自动行为，以观察静态材质；语音口型、表情预览和主动动作仍可使用。
使用保留 sRGB 输出的无色调映射模式（Canvas flat）、中性灰背景及较低强度的主光／补光，作为对比材质与颜色的基线；这不是对 VRoid Hub 参数的复刻，最终观感仍需浏览器截图确认。
新增半身／全身视角；切换视角恢复正面构图。支持鼠标滚轮按相机距离缩放。清晰模式上限 60 FPS，流畅模式上限 30 FPS，均不保证目标设备实际帧率。

## 对话行为联动（2026-10-19）

- 本轮涉及 Java 中继与前端，更新后须重启 Spring Boot 服务，再刷新前端页面。
- WebRTC 事件通道转发 avatar.response 事件及字幕中的 responseId；不增加模型调用，不修改语音生成和工具调用流程。
- 客户端状态由用户语音事件与实际播放路径的音量估计：listening / thinking / speaking / idle。说话短暂停顿采用 350 ms 保持，等待状态最多保持 8 秒，避免事件缺失时一直显示思考姿态。
- 眼神大部分时间看向用户，偶尔短暂偏移；思考状态更容易移开，聆听状态较少移开。目标有停留时间与平滑过渡，眼球角度仍受 VRM 的 LookAt 绑定约束。
- 移除待机时整个人上下浮动，呼吸只轻微作用于胸部。
- 自动表情只识别助手回答中少量明确短语，例如“真为你高兴”“很高兴见到你”“这太意外了”“听到这个消息我很难过”。普通回答保持中性，每个回答最多触发一次。规则不等于语义情绪识别，复杂否定、讽刺和转述仍可能误判。
- 表情强度默认 0.35，持续 2.5 秒；收到线索后等待实际播放开始再应用，无音频 5 秒后丢弃。其同步粒度是回答级，尚无音素或词级时间戳，不保证表情精确对应某一个词。
- 用户打断时，清掉待执行表情并恢复中性，记住被取消的回答 ID；旧回答后续抵达的线索无效。关闭和重连时全部清理。缺少回答 ID 时不自动推断情绪，但口型与手动预览仍可用。
- 新增客户端支持的 avatar.expression 消息包含 responseId、name、weight、durationMs；权重限制在 0～0.7，持续时间限制在 300～5000 ms。当前自动线索由客户端字幕规则产生，服务端尚不主动生成情绪事件。
- 当前身体动作仍是程序化预览，仓库中没有提供 FBX 素材；高质量动作库和 HY-Motion 动作重定向尚待具体文件验证。

建议先测试：告诉角色一个好消息，让其明确表达“真为你高兴”；观察表情随播放出现，然后在回答中打断并开始下一轮，确认旧表情没有重新出现。再切换自然待机，观察眼神和胸部动作。

关键代码：AvatarRuntime.ts（回答和行为状态）、avatarEvents.ts（事件校验与短语规则）、GazeController.ts（注视策略）、AvatarStage.tsx（统一动画混合）。

本轮验证：15 项前端行为／骨骼测试、前端构建和修改文件 lint、两条中继相关测试与完整 Maven verify 均通过。测试环境需要在启动测试 JVM 时预加载 Byte Buddy agent，以避免 Mockito 动态附加的管道权限问题；未改动项目测试配置。

## 真实挥手动画接入（2026-10-20）

已导入 motion-1bdf34d6-68b7-4a81-94a6-f41364afa51f.fbx。原文件约 16 MiB，含 2.97 秒、90 帧动作及网格贴图。
通过 tools/prepare-hy-motion.mjs 提取成 public/animations/wave.motion.json（约 41 KiB），浏览器不再加载原 FBX。

刷新页面，等待“真实挥手动画已就绪”，点击“挥手”预览；“停止动作”会在约 0.25 秒内恢复当前待机姿态。
语音原有 wave 工具指令使用相同素材。仍不具备根据任意回复内容自动规划手势的功能。

- 覆盖脊柱、肩、上臂、前臂、手腕共 11 条旋转轨道；保留当前角色、贴图和手指默认姿态。
- 不应用根位移、髋或腿部动作，保持当前站位和脚部位置；头部、视线、表情和嘴型继续独立驱动。
- 根据标准化左臂方向校正 VRM 0.x / 1.x 坐标差异；缺少可选 upperChest / shoulder 骨骼时合并到可用节点。
- 开始约 0.22 秒淡入，结束前约 0.35 秒回到基础姿态；重复点击从当前显示姿态过渡，用户插话会淡出动作。
- 每帧先还原程序基础姿态再叠加动画，避免动作旋转残留或反馈到下一帧。
- 动作时长由真实素材决定，修复旧 2.5 秒手势上限导致截断的问题。
- 素材加载失败时状态栏明确提示，暂用原基础挥手；切换或隐藏角色时释放播放状态。

实现：WaveAnimation.ts（校验、重定向和混合），AvatarStage.tsx（加载与骨骼分层），AvatarRuntime.ts（动作序号、时长、停止）。

本次验证：前端构建、修改文件 ESLint、23 项前端测试通过。真实 VRM 骨骼测试验证右手抬过肩部、左手下垂、重复播放、打断恢复、非动作骨骼保持及缺失可选骨骼的处理。
